## 一、检索数据存储结构

### 1.1. Chunk 索引（目录：chunks/）

| 字段名         | 类型    | 存储 | 备注                            |
|----------------|---------|------|---------------------------------|
| chunk_id       | ID      | 是   | 主键，不用于全文检索            |
| doc_id         | ID      | 是   | 可用于过滤，但不参与全文搜索    |
| section_title  | TEXT    | 是   | ✅ **被检索字段**               |
| section_path   | TEXT    | 是   | ✅ **被检索字段**               |
| content        | TEXT    | 是   | ✅ **被检索字段**（主要正文）   |
| chunk_index    | NUMERIC | 是   | 序号，不用于全文检索            |
| prev_chunk_id  | ID      | 是   | 上下文链接，不用于检索          |
| next_chunk_id  | ID      | 是   | 上下文链接，不用于检索          |

**检索说明**：`search_chunks` 方法使用 `["content", "section_title", "section_path"]` 三个字段进行全文搜索。

---

### 2.2. Entity 索引（目录：entities/）
| 字段名      | 类型 | 存储 | 备注                            |
|-------------|------|------|---------------------------------|
| entity_id   | ID   | 是   | 主键，不用于全文检索            |
| name        | TEXT | 是   | ✅ **被检索字段**（实体名）     |
| desc        | TEXT | 是   | ✅ **被检索字段**（描述）       |
| entity_type | ID   | 是   | ✅ **被检索字段**（类型词，支持精确/组合搜索） |
| chunk_id    | ID   | 是   | 不用于全文检索                  |
| doc_id      | ID   | 是   | 不用于全文检索                  |

**检索说明**：`search_entities` 方法使用 `["name", "desc", "entity_type"]` 三个字段进行搜索。

---

### 3.3. Relation 索引（目录：relations/）
| 字段名      | 类型 | 存储 | 备注                            |
|-------------|------|------|---------------------------------|
| relation_id | ID   | 是   | 主键，不用于全文检索            |
| subject     | TEXT | 是   | ✅ **被检索字段**（主语）       |
| predicate   | TEXT | 是   | ✅ **被检索字段**（谓词）       |
| object      | TEXT | 是   | ✅ **被检索字段**（宾语）       |
| chunk_id    | ID   | 是   | 不用于全文检索                  |
| doc_id      | ID   | 是   | 不用于全文检索                  |

**检索说明**：`search_relations` 方法使用 `["subject", "predicate", "object"]` 三个字段进行搜索。

> 三个索引均通过 `chunk_id` 和 `doc_id` 与原始文档关联，检索结果可直接映射回内存中的 `Chunk`/`Document` 对象；所有 TEXT 字段都使用结巴分词 + 小写 + 停用词过滤的分析器，支持中文全文搜索。

## 二、检索与打分

### 2.1. 多通道独立检索

系统将查询划分为四个通道，分别在不同索引上执行搜索：

| 通道             | 搜索索引   | 匹配字段                         |
| ---------------- | ---------- | -------------------------------- |
| entity（实体）   | 实体索引   | `name`, `desc`                   |
| relation（关系） | 关系索引   | `subject`, `predicate`, `object` |
| title（标题）    | chunk 索引 | `section_title`, `section_path`  |
| content（内容）  | chunk 索引 | `content`                        |

- 每个通道的查询由 **结构化字段条件** 按 OR 组合而成，分词使用 jieba，支持精确匹配、模糊匹配、子串匹配等策略。
- 若 content 通道存在自由文本（free_text），会额外生成一个低权重（boost=0.3）的 fallback 查询，与原查询取 OR 以提高召回。
- 支持文档级过滤（`doc_ids`），通过 AND 逻辑限定检索范围。

---

### 2.2. 通道内打分
- **Whoosh 底层评分**：各索引默认使用 Whoosh 的评分算法（通常为 BM25F），为每个命中记录返回原始分数。
- **分数聚合**：实体/关系索引可能多条记录对应同一个 chunk_id，此时取该 chunk 在该通道的 **最高得分** 作为代表分数。
- **chunk 索引**：直接以 Whoosh 返回的得分作为该 chunk 在该通道的得分。

---

### 2.3. 跨通道融合
1. **Min‑Max 归一化**：对每个通道内部的分数进行归一化到 [0, 1]，消除不同通道评分尺度差异。
2. **加权求和**：使用 `channel_weights` 中的权重（实体、关系、标题、内容四个通道），先归一化有效通道权重（使和=1），再乘以归一化分数求和：
   \[
   \text{total\_score} = \sum_{ch} \frac{w_{ch}}{\sum w} \cdot \text{norm\_score}_{ch}
   \]
3. **阈值截断**：总分低于 0.01 的 chunk 被丢弃。
4. **排序取 Top‑K**：按总分降序排列，取前 `top_k` 个结果。

{question}

{options}


答题要求：
1. 对边界值的判断从宽处理，仅小数点的差别可以认为在范围内
2. 只要正负关系、限定实体、数值一致即可认为选项正确，不需要过度纠结选项中未提及，但文档中有的提及的范围

请按以下格式输出，直接输出json格式数据，不需要添加额外内容，不需要用```包裹json数据
answer字段，直接输出正确选项
